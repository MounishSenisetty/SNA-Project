# Explainable Centrality GNN

Explainable Centrality GNN is a small research-style graph learning project that predicts node centrality values with a graph neural network and explains those predictions with PyTorch Geometric's `GNNExplainer`.

The default experiment trains on a synthetic Barabasi-Albert graph, generates diffusion-based influence labels with an independent-cascade simulation, fits a GCN regressor, evaluates the model on a held-out node split, and prints explanations for a selected node.

## Core Features

- Node-level regression on graph data.
- Synthetic graph generation for self-contained experiments.
- Optional loading of the Cora citation network.
- Diffusion-based label generation using Monte Carlo simulation.
- Multi-layer GCN model for learning centrality patterns.
- Train, validation, and test splits at the node level.
- Evaluation with regression and rank-based metrics.
- Node explanation with `GNNExplainer`.
- Graph and attribution visualization with Matplotlib.

## Repository Structure

The project is intentionally compact. Each file has a specific role:

- `main.py`: Orchestrates the full pipeline. It reads `config.yaml`, loads the graph, generates labels, trains the model, evaluates it, and runs the explainer.
- `data.py`: Handles reproducibility, synthetic graph creation, optional Cora loading, and train/validation/test mask creation.
- `diffusion.py`: Implements the independent-cascade-style spread simulation used to create target labels.
- `model.py`: Defines the GCN regressor built from `torch_geometric.nn.GCNConv` layers.
- `train.py`: Contains the training step and validation loss helper.
- `evaluate.py`: Computes test metrics using MSE, MAE, Spearman correlation, and Kendall correlation.
- `explain.py`: Wraps PyTorch Geometric's `Explainer` and `GNNExplainer` for node-level explanation.
- `viz.py`: Draws the graph colored by scores and shows feature attribution bars.
- `config.yaml`: Stores all experiment hyperparameters and data settings.
- `requirements.txt`: Lists the Python dependencies needed to run the project.

## How The Pipeline Works

1. A graph is loaded or generated.
2. Node features are attached to the graph.
3. Diffusion labels are generated by repeatedly simulating influence spread from each node.
4. Nodes are split into train, validation, and test subsets.
5. The GCN regressor learns to predict the scalar label for each node.
6. The best validation checkpoint is restored.
7. Test metrics are reported.
8. A selected node is explained with `GNNExplainer`.
9. Optional plots show predicted scores, true scores, and attribution patterns.

## Data And Labels

### Synthetic graph

The default dataset is a Barabasi-Albert graph generated by `networkx.barabasi_albert_graph`. This gives a scale-free graph with hub structure, which is useful for centrality-related tasks.

Each node receives random Gaussian features. The graph is converted to a PyTorch Geometric `Data` object and used directly by the GNN.

### Cora dataset

If `data.type` is set to `cora`, the project loads the standard Planetoid Cora dataset from PyTorch Geometric.

### Diffusion labels

Target labels are not hand-coded centrality values. Instead, `diffusion.py` estimates a node's influence by simulating an independent cascade process many times and averaging the final spread size.

This means the model is learning a diffusion-based notion of centrality or influence rather than a classical graph-theoretic centrality score.

## Model

`model.py` defines `GCNRegressor`, a stack of graph convolution layers followed by a final linear output layer.

Behavior:

- input: node features and `edge_index`
- intermediate layers: graph convolution, ReLU, dropout
- output: one scalar per node

The architecture is controlled by these config values:

- `model.hidden_dim`
- `model.num_layers`
- `model.dropout`
- `model.lr`
- `model.weight_decay`
- `model.epochs`

## Training

Training is handled in `train.py`.

The loop:

- runs full-graph forward passes
- computes MSE loss on the training mask only
- validates on the validation mask after each epoch
- stores the best model state by validation loss

After training, the best checkpoint is restored before evaluation.

## Evaluation

`evaluate.py` reports four test metrics:

- `mse`: Mean squared error
- `mae`: Mean absolute error
- `spearman`: Spearman rank correlation
- `kendall`: Kendall rank correlation

The regression metrics measure numeric error, while the rank correlations show whether the model preserves node ordering.

## Explainability

`explain.py` uses PyTorch Geometric's `Explainer` with `GNNExplainer`.

The explainer is configured for:

- model-level explanation
- node-level task
- attribute masks for node features
- object-level masks for edges

The script prints the explanation object keys and the shapes of the returned masks when available.

## Visualization

`viz.py` contains one plot helper for graph-wide score visualization.

When visualization is enabled, the app can:

- draw the graph with node coloring based on true labels
- draw the graph with node coloring based on predicted labels
- show feature attribution bars for an explained node

The default layout uses a spring layout and a Viridis color map.

## Configuration Reference

`config.yaml` is the main experiment file.

### Top-level settings

- `seed`: Random seed used across NumPy, Python, and PyTorch.

### Data settings

- `data.type`: `synthetic` or `cora`
- `data.synthetic.n`: Number of nodes in the generated graph
- `data.synthetic.m`: Barabasi-Albert attachment parameter
- `data.synthetic.feature_dim`: Number of input features per node

### Diffusion settings

- `diffusion.p`: Activation probability for the cascade process
- `diffusion.mc_runs`: Monte Carlo simulations per node
- `diffusion.max_steps`: Maximum number of cascade steps

### Model settings

- `model.hidden_dim`: Hidden dimension of the GCN layers
- `model.num_layers`: Total number of graph convolution layers
- `model.dropout`: Dropout probability between layers
- `model.lr`: Adam learning rate
- `model.weight_decay`: Adam weight decay
- `model.epochs`: Number of training epochs

### Explainability settings

- `explain.node_id`: Node index to explain
- `explain.topk_edges`: Number of top edges to report
- `explain.topk_features`: Number of top features to report

## Installation

Recommended on Windows:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If `torch_geometric` or its compiled dependencies are difficult to install, follow the official PyTorch Geometric installation guide for the matching PyTorch and Python versions:

https://pytorch-geometric.readthedocs.io/

## Running The App

From the project directory:

```powershell
python main.py
```

If you want to avoid opening windows for plots, use:

```powershell
python main.py --no-viz
```

The app prints training progress, test metrics, and explanation details to the terminal.

## Practical Notes

- Diffusion label generation is the slowest part of the pipeline because it runs many Monte Carlo simulations.
- Reducing `diffusion.mc_runs` makes the project faster for demonstrations.
- The synthetic dataset is the easiest way to run the app end-to-end without downloads.
- Cora requires network access the first time it is downloaded.
- If you are running in a non-interactive environment, use `--no-viz`.

## Troubleshooting

- If `torch_geometric` fails to import, verify that the installed PyTorch version matches the available PyG wheel set for your Python version.
- If `GNNExplainer` raises an error, make sure the model is in evaluation mode and the graph data includes valid `x` and `edge_index` fields.
- If Cora does not download, check the `data/Planetoid` cache directory and your internet connection.
